# ETF 套利研究系统事件驱动架构设计

## 1. 范围与边界

本次改造是事件驱动底座的第一阶段，不改变既有深市研究结果定义，也不增加真实交易能力。
新增底座负责把行情、PCF 和市场状态转成可追溯事件，再组装为现有可执行研究链路使用的完整
`market_data.models.MarketSnapshot`。定价器、质量门禁、机会检测、风险控制和纸面引擎仍只
接收快照，不直接消费原始事件。

明确保持的边界：

- 只做机会识别、历史回放和纸面模拟；
- 不连接券商柜台，不提供真实报单或撤单；
- 缺少 ETF 或完整成分篮子的 Bid/Ask 时，不产生可执行快照；
- Premium 收敛研究仍不解释为申赎套利收益；
- 现有图表继续不绘制官方 IOPV；
- SSE 只定义能力契约和缺口，不伪造交易规则。

## 2. 改造前后的数据流

### 2.1 改造前

项目当前存在两条并行研究链路：

```text
均值回复研究
DataFeed
-> data.models.MarketSnapshot
-> IOPV / PremiumMonitor / RiskEngine / Signal
-> Backtest / observations / dashboard

可执行纸面模拟
MarketDataSource
-> market_data.models.MarketSnapshot
-> DataQualityChecker / BasketPricer
-> ArbitrageDetector / RiskEngine
-> PaperArbitrageEngine / RunRecorder / dashboard
```

两个 `MarketSnapshot` 服务于不同历史链路。第一阶段不合并它们，避免改变旧结果口径。事件
底座只向可执行纸面模拟链路投影 `market_data.models.MarketSnapshot`；均值回复链路保持原样。

### 2.2 改造后

```text
原始行情 / PCF / 市场状态
-> ExchangeAdapter（交易所和供应商差异收口）
-> EventEnvelope（统一、不可变、可版本化）
-> FileEventStore（先落盘） + InMemoryEventBus（进程内发布）
-> SnapshotAssembler（状态投影、完整性判断、事件链追踪）
-> market_data.models.MarketSnapshot
-> 现有质量门禁 / 定价 / 机会检测 / 风控 / 纸面引擎
-> Snapshot、机会、拒绝、风险和纸面执行事件
-> 研究结果与 Dashboard 投影
```

Dashboard 不是事件状态的所有者。事件日志和 SnapshotAssembler 才是可回放状态来源。

## 4. 统一证券标识

所有新增领域事件使用：

```python
InstrumentId(exchange=Exchange.SZSE, code="159915")
```

稳定键为 `SZSE:159915`。同一六位代码在不同市场不再被视为同一证券。ETF 的上市市场和
每只成分证券的交易市场分别表达。

当前可执行快照为了兼容旧定价器，`component_order_books` 仍以六位代码为键。这个兼容映射
只发生在 SnapshotAssembler 最后一层，并执行歧义检查：若一个篮子中出现相同代码、不同
交易所，则拒绝组装，而不是静默覆盖。后续定价器完全迁移到 `InstrumentId` 后可删除该兼容层。

## 5. 核心事件模型

`EventEnvelope` 至少保留：

- 业务身份：`event_id`、`event_type`、`schema_version`；
- 时间：`event_time`、`received_time`、`trade_date`；
- 来源：`source`、`exchange`、`instrument_id`、`sequence_number`；
- 因果：`correlation_id`、`causation_id`；
- 内容：不可变 `payload`、`payload_hash`。

`payload_hash` 由规范化 JSON 计算。`event_id` 由业务时间、来源、证券、序号、Schema 和
载荷哈希生成，不包含本机接收时间，因此同一业务事件即使再次接收仍得到相同 ID。事件总线、
事件存储和 SnapshotAssembler 分别进行幂等保护。

已建模的事件族包括：

- 行情：盘口、最新价、交易状态、官方 IOPV、序号断档、数据源断连和重连；
- PCF：发布、校验、拒绝、修订、成分、替代规则、申赎状态和限额变化；
- 市场运行：交易日开始/结束、交易阶段变化；
- 研究与风险：快照组装/拒绝、机会、风险阻断/解除；
- 纸面执行扩展：虚拟订单、虚拟成交、模拟申赎和现金差额结算。

最后一类目前只是标准事件接口，不代表真实执行能力。

## 6. 事件存储与确定性回放

默认存储是本地 JSONL：

```text
data/events/
  YYYYMMDD/
    SZSE/
      OrderBookUpdated.jsonl
      PCFValidated.jsonl
      SnapshotAssembled.jsonl
    SSE/
  _checkpoints/
```

写入特点：

- 单事件追加并立即刷新到磁盘；
- 按交易日、交易所、事件类型分区；
- 分区内按稳定 `event_id` 去重；
- 消费者检查点通过临时文件替换实现原子提交；
- 回放按事件时间、证券、来源、序号、接收时间和事件 ID 的稳定组合排序；
- 指定 `end` 时只读取 `event_time <= end`，不会使用未来事件。

第一阶段不引入 Kafka。`EventBus` 和 `EventStore` 是协议，后续替换基础设施不需要改动策略。

## 7. SnapshotAssembler 状态与转换

SnapshotAssembler 维护：

- 当前有效 PCF 及产生它的事件 ID；
- ETF 与成分证券的最新盘口；
- 官方 IOPV；
- 每个来源和证券的最新序号及断档状态；
- 数据源断连状态；
- 最大事件时间与事件时间水位；
- 已处理事件 ID。

状态转换如下：

```text
无 PCF
  --PCFValidated/PCFRevised--> 已有有效 PCF + 原子替换依赖图

无/不完整盘口
  --OrderBookUpdated---------> 重新组装受影响 ETF

完整中间价但缺少双边盘口
  ---------------------------> INDICATIVE

PCF、ETF 和全部必需成分双边盘口完整
  ---------------------------> EXECUTABLE

跨交易日、未来报价、代码歧义、序号断档、来源断连
  ---------------------------> REJECTED
```

每次成分证券事件只通过反向依赖图重算相关 ETF。PCF 切换先构造新集合，再一次性替换旧依赖，
因此不会在新旧篮子之间暴露混合状态。

组装结果保留：

- `trigger_event_id`：触发本次计算的事件；
- `trace_event_ids`：PCF、ETF 盘口、成分盘口和 IOPV 的完整输入链；
- `pcf_version` 与 `pcf_hash`；
- `event_watermark`；
- `assembly_blockers`；
- `EXECUTABLE`、`INDICATIVE` 或 `REJECTED` 状态。

## 8. PCF 通用化与差分

现有 `PCFDocument` 和 `PCFComponent` 采用新增默认字段的方式扩展，旧构造调用无需修改。新增
元数据包括上市市场、成分市场、Schema 版本、解析器版本、文件哈希、申赎机制、单账户限额、
账户要求、结算规则和原始字段。

深市 XML 解析继续复用 `SZSEPCFParser`；沪市使用上交所基金网站公开查询接口的头部和成分
JSON，由 `SSEPCFParser` 归一到相同模型。两者均补充源文件 SHA256 与解析元数据，交易所
特有字段放入 `raw_fields` 供审计。

PCF Diff 能识别：

- 成分新增、删除和组合证券数量变化；
- 现金替代标志、溢价率、折价率和替代金额变化；
- 申购/赎回开关和限额变化；
- 最小申赎单位、申赎机制、上市或成分市场变化；
- Schema、账户与结算要求变化。

差分事件固定带有 `holdings_inference="NOT_ESTABLISHED"`：PCF 成分变化不能直接解释为基金
已经完成实际调仓。

## 9. 交易所适配

`SZSEAdapter` 当前复用：

- `SZSEPCFParser`；
- `SZSEMarketSchedule`；
- `.SZ` 供应商代码编解码；
- 已标准化 `OrderBook` 到领域事件的转换。

它明确标记为非生产就绪，未连接 RuleBook、SettlementModel、账户或券商。

`SSEAdapter` 已提供 `.SH` 代码编解码与公开 PCF JSON 解析，能保留 `101/102/103/105/106`
挂牌市场、0-8 现金替代标志、申购溢价率、赎回折价率和官方原始字段。行情 Redis 键按
`InstrumentId` 自动生成 `.SH/.SZ/.HK/.BJ` 后缀。

下一阶段仍需补齐并通过账户、行情和结算证据验证：

1. 沪市交易阶段、停复牌、涨跌停和官方节假日日历；
2. 各现金替代标志在申购、赎回和退补方向上的最终资金语义；
3. 申赎限额、账户资格和基金公司修订文件优先级；
4. 结算时点、份额与证券可用规则；
5. 沪市行情字段、序号、重连和断档语义；
6. 沪深同时回放时的时钟、水位和跨市场数据完整性。

因此沪市 PCF 可用于篮子与规则研究，但适配器仍明确标记为非生产就绪。

## 10. 向后兼容

- 原 `DataFeed`、Redis 采集、JSONL 记录和回放入口未改签名；
- 原均值回复 `data.models.MarketSnapshot` 未修改；
- 可执行链路的 `market_data.models.MarketSnapshot` 仅增加有默认值的追踪字段；
- PCF 模型新增字段均有兼容默认值，原深市字段和计算口径保持；
- 原质量门禁、定价、风险和纸面引擎不直接依赖事件模块；
- Dashboard 未承担事件总线或投影状态；
- `data/events/` 与原始记录、观察结果和运行结果分开，并默认忽略版本控制。

## 12. 下一阶段建议

建议按以下顺序扩展事件型研究：

1. 把现有质量门禁、机会检测、风险阻断和纸面执行结果映射为标准结果事件；
2. 加入交易阶段、停复牌、涨跌停与成分公司行为事件；
3. 以 PCF Diff 建立指数调样和申赎规则变化研究，不推断真实持仓；
4. 在现有 SSE 官方 PCF 解析基础上补齐日历、行情、账户与结算证据，再做沪深跨市场全实物申赎研究；
5. 引入 HKEX 与 FX 适配，分离本地市场时钟、币种、汇率时点和结算日；
6. 为 QDII ETF 增加跨时区估值、休市错配、延迟 NAV/IOPV 和外汇可用性状态；
7. 在事件量确实超过本地实现能力后，再评估异步总线或外部日志系统。

尚未解决的主要风险是：沪市 PCF 格式已用官方公开数据验证，但账户、结算和生产行情规则
尚未验证；当前事件落盘为单进程本地实现；旧定价器仍使用六位成分代码兼容键；实盘数据源
的序号、重连和交易状态语义需逐供应商校验；跨市场时钟、汇率、公司行为、账户权限和结算
可用性尚未进入快照完整性判断。
