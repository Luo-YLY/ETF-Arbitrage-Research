# 事件驱动扩展落地、数据需求与实盘差距报告

更新日期：2026-07-29

## 1. 结论

本轮已经把当前不依赖券商专有接口、交易所未验证规则或真实账户权限的扩展全部落地为可运行代码，而不是只写占位设计：

1. 现有 `MarketSnapshot` 可以拆成标准行情事件，再由 `SnapshotAssembler` 重新组装，验证了“快照模式 → 事件模式 → 兼容快照”的迁移路径。
2. 交易所适配器可以注册、查询和输出能力矩阵；深市能力与沪市缺口被机器可读地分开表达。
3. 深市交易阶段可以输出 `TradingDayStarted`、`SessionPhaseChanged` 和 `TradingDayEnded`，相同阶段的重复轮询不会重复发事件。
4. 完整快照可以继续交给现有 `ExecutableArbitrageDetector`，并输出机会、拒绝和风险状态事件。
5. 现有纸面引擎的订单、成交、模拟申赎、确认/拒绝和最终现金差额可以投影为标准事件。
6. 回放可以只选择原始事件，清空投影状态后重建快照与研究结果；同一时刻固定按“市场日历/PCF → 行情 → 派生结果”排序。
7. 新增审计索引可按 `causation_id`、`correlation_id` 和 `event_id` 查询因果链及下游事件。
8. `MarketSnapshot` 同时保留旧的六位成分代码映射和新的 `交易所:代码` 映射，现有深市定价器无需迁移即可继续运行。

当前结果仍然是研究与纸面模拟系统。代码中没有券商连接、真实报单、撤单、账户查询或真实申赎提交能力。

## 2. 新数据流

```text
现有快照 / Redis标准化行情 / 文件回放 / PCF / 市场时钟
  -> 交易所与供应商适配
  -> 不可变 EventEnvelope
  -> FileEventStore + InMemoryEventBus
  -> SnapshotAssembler + ETF反向依赖图
  -> 不可变 MarketSnapshot
  -> 现有质量门禁与 ExecutableArbitrageDetector
  -> 机会 / 拒绝 / 风险状态事件
  -> 可选 PaperArbitrageEngine
  -> 纸面订单 / 成交 / 模拟申赎 / 现金差额事件
  -> EventAuditIndex / 报告 / Dashboard投影
```

原始事件不会直接进入定价器。定价、质量检查和纸面引擎仍只接收完整 `MarketSnapshot`。

## 3. 本轮落地模块

| 模块 | 已实现能力 | 明确边界 |
| --- | --- | --- |
| `exchanges/registry.py` | 适配器注册、按交易所查找、能力矩阵 | 能力存在不等于生产就绪 |
| `eventing/market_clock.py` | 交易日及阶段的边沿触发事件 | 当前只有深市简化交易时段；未接官方节假日日历 |
| `eventing/adapters.py` | 将现有标准化快照拆为盘口与官方 IOPV 事件 | 不负责解析供应商原始二进制/私有字段 |
| `eventing/opportunity_engine.py` | 装配快照进入现有可执行研究检测器 | 只输出研究结论，不下单 |
| `eventing/projectors.py` | 机会、拒绝、风险和纸面执行结果事件化 | “research_executable”不等于“live_executable” |
| `eventing/audit.py` | 因果链、相关链、下游事件和缺失父事件检查 | 是选定事件范围内的只读索引 |
| `eventing/pipeline.py` | 批量输入、派生事件发布、回放发布器和投影重置 | 仍是单进程本地实现 |
| `eventing/replay.py` | 按事件类型、交易所、证券和时间筛选回放 | 未实现跨进程消费协调 |
| `market_data/models.py` | 新增完整交易所限定的成分盘口映射 | 旧定价器暂时仍使用六位代码兼容映射 |

## 4. 事件结果语义

### 4.1 机会事件

每个完整快照分别评估申购和赎回方向：

- 可通过当前价格、深度、费用、限额和质量门禁时，输出 `OpportunityDetected`；
- 任一条件不满足时，输出 `OpportunityRejected`，保留方向和拒绝原因；
- 载荷同时包含毛利润、估计费用、安全缓冲、净利润、bps、最大可执行 CU 和瓶颈；
- 固定写入 `research_only=true`、`live_executable=false`，防止研究结果被误解为可直接报单。

### 4.2 风险事件

`RiskBlocked` 与 `RiskUnblocked` 采用状态变化触发：

- 初次进入阻断状态时发 `RiskBlocked`；
- 阻断原因变化但状态仍为阻断时不制造重复状态事件；
- 从阻断恢复为可研究执行时发 `RiskUnblocked`；
- 序号断档、跨日 PCF、非法盘口等严重问题仍可触发 kill switch。

### 4.3 纸面执行事件

只有调用现有纸面引擎并取得结果后才投影：

- `PaperOrderCreated`
- `PaperOrderFilled`
- `CreationRedemptionRequested`
- `CreationRedemptionConfirmed`
- `CreationRedemptionRejected`
- `CashAdjustmentSettled`

所有订单和一级市场请求均明确标注 `paper_only`、`emulated` 或 `live_order=false`。事件层没有新增真实执行入口。

## 5. SnapshotAssembler 与跨市场兼容

当前 `MarketSnapshot` 有两套并存的成分映射：

```text
component_order_books["600000"]       # 旧定价器兼容键
qualified_component_order_books[
    "SSE:600000"
]                                      # 新事件与跨市场键
```

组装时先按 PCF 中每只成分的 `InstrumentId` 查找盘口，再生成兼容映射。如果同一篮子出现“代码相同、交易所不同”的冲突，组装器拒绝产生可执行快照，而不是覆盖其中一只证券。

PCF 更新会一次性替换 ETF 依赖集合。成分行情只触发依赖该成分的 ETF 重算，不扫描全部 ETF。

## 6. 数据支持清单

### 6.1 当前研究链路已经可以使用

| 数据 | 当前来源/状态 | 能支持的结论 |
| --- | --- | --- |
| 深市 PCF XML | 已有解析、校验、哈希和版本元数据 | 篮子结构、申赎单位、现金替代和限额研究 |
| 沪市 PCF JSON | 上交所公开头部/成分查询接口，已归一解析并保留原始字段 | 沪市篮子、挂牌市场、替代标志和申赎约束研究 |
| ETF/成分最新价 | Redis或历史记录 | Premium与指示性偏离研究 |
| ETF/成分 Bid/Ask及深度 | 模拟、标准文件或未来实时源 | 纸面可执行篮子价格与容量 |
| 停牌、涨跌停、盘口完整性 | 标准 `OrderBook` 字段 | 质量门禁和机会拒绝 |
| 官方 IOPV | 可选事件字段 | 内外 IOPV 偏差诊断；不绘入现有价格图 |
| PCF 版本变化 | PCF Diff | 规则/篮子变化事件；不能推断基金真实调仓 |

只有最新价而没有真实 Bid/Ask 时，系统只能输出指示性 Premium 研究，不能形成可执行申赎套利结论。

### 6.2 沪市扩展仍需补齐

已取得并落地的是官方公开 PCF 头部/成分 JSON、ETF 及成分挂牌市场映射、0-8 替代标志、
申购溢价率、赎回折价率和申赎限额字段。仍缺：

1. 沪市交易阶段、集合竞价、连续竞价、临停、停复牌、涨跌停和官方节假日日历；
2. 沪市现金替代类型在申购、赎回和事后退补方向上的最终资金语义；
3. 账户资格、券商申赎接口与基金公司修订文件优先级；
4. 份额、证券与现金何时可用的清算交收规则；
5. 行情序号、快照/增量类型、重连补包和断档判定；
6. 至少一组经人工核对的 PCF + 实盘行情 + 真实申赎回报测试夹具。

因此 `SSEAdapter` 已能解析 PCF，但仍保持 `production_ready=False`。

### 6.3 沪深跨市场股票 ETF 还需要

- 两市统一时钟、同一交易日认定和各自水位；
- 跨市场成分的独立停复牌与涨跌停状态；
- 全实物、现金替代和组合证券交付差异；
- 两市行情延迟和供应商时间戳可比性；
- 证券在账户中的可用、冻结、在途和可卖状态；
- 申赎确认之前暴露的未对冲市场风险；
- 跨市场篮子的费用、过户、结算和失败处理。

### 6.4 港股通 ETF / 港股 ETF 还需要

- HKEX 证券主数据、交易单位、价格档位、交易币种和交易日历；
- 港股通可买/可卖名单、额度、投资者资格和节假日错配；
- CNY/HKD 实时可交易汇率、报价时间、点差、额度和换汇结算；
- 台风/黑雨、半日市、竞价时段和市场状态；
- 公司行为、碎股、印花税、交易征费及交收失败；
- 港股与内地份额/证券的真实可用时点。

### 6.5 QDII ETF 还需要

- 境外底层市场日历和时区；
- 标的指数、期货、现货及外汇的同步或错时行情；
- NAV/IOPV 发布频率、延迟、估值来源和节假日错配；
- 申购暂停、额度、外汇可用性、估值调整和大额现金替代；
- 跨日持有、隔夜跳空和无法同步对冲的风险模型。

## 7. 与实盘操作的关键差异

| 环节 | 当前系统 | 实盘必须具备 |
| --- | --- | --- |
| 行情 | 标准快照、文件、模拟或当前 Redis 字段 | 交易所级增量/快照协议、序号恢复、双线路、时钟同步 |
| PCF | 文件解析、版本和哈希 | 官方每日发布、修订推送、完整校验、异常回退和人工确认 |
| 机会 | 按盘口深度与配置费用计算 | 可交易费率、实时资金/证券占用、账户级额度和实际排队概率 |
| 风控 | 数据质量和研究配置门禁 | 柜台前置风控、账户限额、合规限制、熔断、人工 kill switch |
| 订单 | 内存中的 `SimulatedOrder` | 报单/撤单协议、柜台确认、交易所订单号、拒单与重连对账 |
| 成交 | 按盘口模拟扫单 | 部分成交、队列位置、成交回报乱序、重复回报和成交修正 |
| 申赎 | `PrimaryMarketEmulator` | 真实申赎资格、篮子冻结、提交回报、失败撤回和管理人确认 |
| 账户 | 本地模拟现金、库存和 PnL | 柜台资金、持仓、可用/冻结/在途、融资融券和日终对账 |
| 结算 | 配置化延迟和现金差额 | 登记结算回报、最终现金差额、证券到账、失败与补款 |
| 可用性 | 单进程、本地 JSONL | 主备、心跳、监控、灾备、权限、密钥、审计留痕和运维值守 |
| 性能 | 研究级 Python 同步事件总线 | 延迟预算、背压、批量/增量解析、容量测试和故障注入 |

因此，“当前模型判定可执行”准确含义是：在输入盘口、PCF和配置费用均可信的前提下，纸面模型未发现阻断条件。它不代表真实账户一定能成交、申赎或结算。

## 9. 下一阶段建议

### 第一优先级：继续完成沪市“有证据的适配”

公开 PCF 解析已经完成；下一步用实际行情、账户与申赎回报夹具补日历、行情事件和规则验证。
在这些缺口通过测试前，不启用沪深全实物申赎研究。

### 第二优先级：事件型策略

在现有 PCF Diff 上增加研究策略，但严格区分：

- PCF篮子变化；
- 指数公告或公司行为；
- 基金真实持仓变化；
- 申赎规则临时调整。

PCF变化只能作为事件研究输入，不能直接推断基金已经完成调仓。

### 第三优先级：实盘前置层

单独建设 `BrokerGateway`、`AccountSnapshot`、`OrderStateMachine`、`ExecutionReport` 和 `ReconciliationService`。在此之前，当前 `EventDrivenOpportunityEngine` 的输出只能连接纸面引擎。

## 10. 仍未解决的风险

1. 深市市场日历目前是工作日和固定时段模型，尚未接官方节假日、临时休市和竞价细节。
2. 当前 Redis 实际字段若只有最新价，无法证明 Bid/Ask 可执行性。
3. 旧定价器仍使用六位代码兼容键；新事件和组装层已经避免冲突，但定价器尚未完全迁移至 `InstrumentId`。
4. 本地 JSONL 与同步总线适合研究和可审计回放，不具备生产级高可用、背压和跨进程一致性。
5. 费用、融资、券源和一级市场延迟仍是配置或模拟值。
6. 沪市 PCF 已用官方公开数据验证，但沪市账户/结算、港股和 QDII 规则尚未验证。
7. 纸面成交没有真实队列位置、撤单竞争、部分成交后申赎失败和日终差错处理。

这些风险不会被代码静默降级为“实盘可用”；适配器能力矩阵和事件载荷会继续明确标记研究边界。
